# Documentation NOMANA-IT

> Documentation de la suite NOMANA-IT — Framework Liberty, NomaUBL (facturation électronique), Nomasx-1 / Nomajde (JD Edwards) et outils API JDE. Texte intégral : https://docs.nomana-it.fr/llms-full.fr.txt.


## Framework Liberty & applications

- [Assistant IA](https://docs.nomana-it.fr/fr/liberty/framework/ai-assistant/): Le framework propose un assistant Anthropic avec usage d'outils sur /chat. Chaque requête SQL et chaque endpoint HTTP des connecteurs accessibles à l'appelant devient un outil que l'assistant peut sélectionner. Configuration via ANTHROPIC_API_KEY, contrat de génération des outils, filtrage par rôle et historique des conversations.
- [Internationalisation](https://docs.nomana-it.fr/fr/liberty/framework/apps/i18n/): Comment le framework choisit la langue des libellés, des entrées de dictionnaire et des messages d'erreur — en-tête de requête X-Liberty-Lang, préférence par utilisateur, repli sur la valeur par défaut. Comment ajouter une nouvelle langue et surcharger les libellés par application ou par environnement.
- [Applications](https://docs.nomana-it.fr/fr/liberty/framework/apps/overview/): Une application Liberty regroupe connecteurs, écrans, menus, tableaux de bord, graphiques et jobs autour d'un domaine métier. Les applications sont affichées dans le sélecteur d'espace de travail en haut de la barre latérale, éditées par entité depuis chaque onglet de Paramètres, et empaquetées en exports zip pour le transfert entre environnements.
- [Plugins](https://docs.nomana-it.fr/fr/liberty/framework/apps/plugins/): Comment écrire du code Python personnalisé que le framework appelle — appels d'étape de job Nomaflow, validateurs de mot de passe, hooks de dispatch. Déposer un module Python sous liberty-apps/plugins/, le référencer par son chemin d'import depuis le TOML, le framework câble sys.path et l'appelle avec le contexte d'exécution.
- [Construire l'arbre](https://docs.nomana-it.fr/fr/liberty/framework/build/menus/build-the-tree/): L'éditeur d'arbre — ajouter dossiers et éléments, glisser pour réordonner, indenter/désindenter pour reparenter, dupliquer, renommer, rechercher les usages. Le bouton exact et le comportement de chaque action.
- [Types d'éléments](https://docs.nomana-it.fr/fr/liberty/framework/build/menus/item-types/): Les quatre types de feuilles — query / endpoint / dashboard / page — ce qu'ouvre chacun, la forme du champ target, la règle du connecteur, et quand recourir à chacun.
- [Transformer un connecteur en application](https://docs.nomana-it.fr/fr/liberty/framework/build/menus/make-connector-an-app/): Un connecteur devient une « application » visible dans le sélecteur en haut quand un menu lui est attaché et que show_in_switcher est actif. Plus comment le champ optionnel home décide de la page d'accueil.
- [Menus — vue d'ensemble](https://docs.nomana-it.fr/fr/liberty/framework/build/menus/overview/): La page Menus, le modèle de liste à plat reliée par parent, les quatre types de feuilles (query / endpoint / dashboard / page), et comment l'ajout d'un menu transforme un connecteur en application.
- [Permissions et rôles](https://docs.nomana-it.fr/fr/liberty/framework/build/menus/permissions-and-roles/): Le filtre roles sur un élément de menu, la permission sql / api sous-jacente héritée de la cible, comment les dossiers vides se replient, et comment le menu s'élague pour chaque utilisateur.
- [Traductions et icônes](https://docs.nomana-it.fr/fr/liberty/framework/build/menus/translations-and-icons/): Libellés par langue avec la table `l` (l.fr, l.de, …) et noms d'icônes Lucide sur les éléments de menu. Conventions et règles de repli pour les deux.
- [Packages](https://docs.nomana-it.fr/fr/liberty/framework/build/packages/): Transporter la configuration d'une installation Liberty vers une autre. Settings → Package : sélectionner quelques écrans / entrées de menu / tableaux de bord comme amorces, le résolveur de dépendances parcourt tout ce qu'ils atteignent (requêtes, dictionnaire, graphiques) et le package est exporté sous forme de ZIP. Sur l'installation cible, téléverser le ZIP et choisir une stratégie de fusion (merge / overwrite / replace all). La même interface gère les deux côtés.
- [Déployer et déboguer](https://docs.nomana-it.fr/fr/liberty/framework/build/plugins/deploy-and-debug/): Disposition du dépôt des applications, LIBERTY_APPS_DIR, le shell de développement avec uvicorn --reload, le schéma de déploiement en production, les lignes de log à rechercher et la configuration des tests.
- [Primitives ETL](https://docs.nomana-it.fr/fr/liberty/framework/build/plugins/etl-primitives/): La boîte à outils liberty.etl — six helpers asynchrones que les callables de plugin composent en flux ETL : copy_query_to_table, snapshot_rows, delete_rows, truncate_table, insert_audit_record, run_query.
- [Plugins — vue d'ensemble](https://docs.nomana-it.fr/fr/liberty/framework/build/plugins/overview/): Un plugin est un package Python sur disque que Liberty rend importable au démarrage. Il porte les callables personnalisés que les étapes python de Nomaflow référencent — la voie d'extension pour tout ce que les étapes déclaratives ne savent pas exprimer.
- [Écrire un callable](https://docs.nomana-it.fr/fr/liberty/framework/build/plugins/write-a-callable/): Le contrat de fonction d'une étape python — signature, kwargs auto-injectés (connectors / ctx / settings), normalisation de la valeur de retour, synchrone vs asynchrone, sémantique des erreurs et de l'annulation.
- [Dupliquer une requête ou un connecteur](https://docs.nomana-it.fr/fr/liberty/framework/build/queries/clone/): Dupliquer une requête au sein d'un connecteur, dupliquer toutes les requêtes CRUD d'une table, ou dupliquer une application entière (connecteur + dictionnaire + écrans + menu + tableaux de bord + graphiques).
- [Créer une requête personnalisée](https://docs.nomana-it.fr/fr/liberty/framework/build/queries/create-custom/): Écrire une requête isolée à la main — l'onglet Non classées, le formulaire d'éditeur, la bascule writable, le bloc params, l'éditeur SQL avec autocomplétion.
- [Créer depuis une table de base](https://docs.nomana-it.fr/fr/liberty/framework/build/queries/create-from-database/): L'Assistant CRUD — pointez Liberty sur une table existante, cochez les colonnes, obtenez les quatre requêtes CRUD générées et enregistrées en un clic.
- [Requêtes — vue d'ensemble](https://docs.nomana-it.fr/fr/liberty/framework/build/queries/overview/): Organisation de la page Connecteurs de Liberty — Tables / Non classées / Séquences / Recherches — et les quatre types de requêtes que gère chaque onglet.
- [Liaison de paramètres](https://docs.nomana-it.fr/fr/liberty/framework/build/queries/parameter-binding/): Comment les paramètres `:placeholder` reçoivent une valeur à l'exécution — valeurs par défaut déclarées, sources de colonnes d'écran, tokens intégrés `#LOGIN_USER#` / `#SYSDATE#` et surcharges littérales par appel.
- [Variantes SQL par dialecte](https://docs.nomana-it.fr/fr/liberty/framework/build/queries/per-dialect-sql/): Livrer une requête Liberty unique avec un SQL différent sur Postgres, Oracle, MySQL, SQL Server, SQLite et DB2 — la map `sql` par dialecte, quand l'utiliser, les pièges courants.
- [Séquences et recherches](https://docs.nomana-it.fr/fr/liberty/framework/build/queries/sequences-and-lookups/): La fenêtre Scaffold — sélectionnez une table et une colonne, obtenez une requête de séquence (prochain id) ou de recherche (valeur + libellé) générée et l'entrée correspondante du dictionnaire, enregistrées en un clic.
- [Assistant de création d'écran](https://docs.nomana-it.fr/fr/liberty/framework/build/screen-assistant/): Un assistant guidé qui construit un écran complet en une seule passe, à partir de tables (avec jointures) ou d'une requête de connecteur existante. Choix de la source, sélection des colonnes affichées dans la grille (vue partagée par défaut), disposition optionnelle des colonnes dans des onglets de dialogue, revue du dictionnaire, placement du menu, création.
- [Actions et cycle de vie](https://docs.nomana-it.fr/fr/liberty/framework/build/screens/actions-and-lifecycle/): L'onglet Actions — boutons de barre d'outils, menu contextuel ligne, hooks de dialogue (on_load / on_save / on_cancel), hooks de ligne (on_insert / on_update / on_delete), et les sept types d'action principaux.
- [Colonnes](https://docs.nomana-it.fr/fr/liberty/framework/build/screens/columns/): L'onglet Colonnes — définir une fois le titre d'affichage, le format, la référence dictionnaire, la règle d'édition, la valeur par défaut et le filtrage de chaque colonne ; la grille et le dialogue les utilisent tous deux.
- [Champs conditionnels](https://docs.nomana-it.fr/fr/liberty/framework/build/screens/conditional-fields/): Faire apparaître un champ de dialogue, le rendre obligatoire ou le verrouiller uniquement quand un autre champ a une valeur précise — visible_when / required_when / disabled_when sur ColumnHint et ScreenField.
- [Créer un écran à partir d'une requête](https://docs.nomana-it.fr/fr/liberty/framework/build/screens/create-from-query/): Câbler une requête `_get` sur un nouvel écran — l'onglet Général et l'onglet Requêtes parcourus champ par champ ; la grille apparaît, les modifications passent par les requêtes d'écriture.
- [Constructeur de dialogue](https://docs.nomana-it.fr/fr/liberty/framework/build/screens/dialog-builder/): Le Constructeur visuel — un canevas à trois colonnes style Figma (Palette / Canevas / Inspecteur) où l'on glisse des champs sur des onglets, on définit les propriétés, on câble les recherches et on ajoute des actions par onglet.
- [Onglets imbriqués](https://docs.nomana-it.fr/fr/liberty/framework/build/screens/nested-tabs/): Intégrer un formulaire d'enregistrement enfant (nested_form) ou une grille de lignes liées (nested_table) dans un onglet de dialogue — même dialogue, plusieurs sources de données.
- [Écrans — vue d'ensemble](https://docs.nomana-it.fr/fr/liberty/framework/build/screens/overview/): La page Écrans — barre de portée à gauche avec les applications, liste à plat des écrans, clic pour ouvrir les 7 onglets du Concepteur d'écran (Général / Requêtes / Colonnes / Dialogue / Actions / Menu contextuel ligne / Export).
- [Secrets chiffrés](https://docs.nomana-it.fr/fr/liberty/framework/build/secure/encrypted-secrets/): Le switch 🔒 qui chiffre les champs secrets au repos — ce qui est chiffré, comment AES-256-GCM est câblé, où réside la clé maîtresse, le préfixe ENC: et le scénario de rotation.
- [Clé de licence](https://docs.nomana-it.fr/fr/liberty/framework/build/secure/license-key/): Ce que la licence conditionne (les produits éditeur packagés — Nomasx-1, Nomajde, NomaUBL …), où la renseigner (Paramètres → Application est le chemin canonique ; la variable d'environnement LIBERTY_LICENSE_KEY reste disponible en repli) et ce qui se passe quand elle est absente ou expirée.
- [Sécurité — vue d'ensemble](https://docs.nomana-it.fr/fr/liberty/framework/build/secure/overview/): Qui peut se connecter (local ou OIDC), ce qu'ils peuvent faire (rôles + permissions avec grammaire allow/deny) et ce qui est chiffré au repos. Les deux couches du modèle de sécurité Liberty.
- [Rôles et permissions](https://docs.nomana-it.fr/fr/liberty/framework/build/secure/roles-and-permissions/): Composer les rôles avec le PermissionPicker — baseline (Aucun accès / Accès complet) plus règles d'autorisation / de refus par surface. La grammaire complète, l'ordre de résolution, les recettes standard.
- [Se connecter — local et OIDC](https://docs.nomana-it.fr/fr/liberty/framework/build/secure/sign-in/): Choisir le backend d'identité (TOML ou DB), configurer les utilisateurs locaux, activer en option l'OIDC sur n'importe quel fournisseur conforme (Keycloak, Azure AD, Auth0, Okta…). Ce que voit l'utilisateur à la connexion.
- [Utilisateurs](https://docs.nomana-it.fr/fr/liberty/framework/build/secure/users/): L'onglet Paramètres → Accès → Utilisateurs — ajouter des utilisateurs locaux, gérer les utilisateurs OIDC arrivés à la première connexion, attribuer des rôles, basculer is_active et is_superuser, réinitialiser les mots de passe.
- [Paramètres de l'application](https://docs.nomana-it.fr/fr/liberty/framework/build/settings-app/): Paramètres → App est l'éditeur maître de app.toml — quatre sections repliables (App, Licence, Assistant IA, OpenID Connect) couvrant l'hôte/le port, la clé de licence, la configuration de l'assistant IA et le SSO OIDC. Les champs sensibles (license.key, ai.api_key, oidc.client_secret) transitent masqués et sont chiffrés au repos avec la clé maître d'installation. La plupart des changements prennent effet à chaud — seuls host / port / log_level imposent un redémarrage du serveur.
- [Graphiques](https://docs.nomana-it.fr/fr/liberty/framework/charts/): Un graphique enveloppe une requête de connecteur dans une visualisation rendue par Recharts. Défini dans Paramètres → Graphiques, choisi dans le constructeur par type (line, bar, column, pie, donut, area, scatter), avec les champs d'axe, les séries, les couleurs, la légende et l'intervalle de rafraîchissement réglés dans le même formulaire.
- [Paramètres du framework](https://docs.nomana-it.fr/fr/liberty/framework/configuration/app-toml/): Tous les paramètres transverses du framework — nom de l'application, pool de base par défaut, backend d'authentification, OIDC, fournisseur IA, clé maîtresse de chiffrement, licence — se modifient depuis Paramètres → Framework. Le formulaire est piloté par un schéma ; cette page liste chaque champ, son rôle et l'endroit où il s'applique.
- [Historique & versionnage de la configuration](https://docs.nomana-it.fr/fr/liberty/framework/configuration/config-history/): Chaque sauvegarde de configuration est capturée, chaque sauvegarde d'écran capture sa clôture de dépendances sous forme de bundle restaurable, les changements de version sont journalisés et les notes de version se lisent dans l'application — le tout sous Paramètres → Historique.
- [Chiffrement et secrets](https://docs.nomana-it.fr/fr/liberty/framework/configuration/encryption-secrets/): Les mots de passe de connecteurs, les jetons d'API et les secrets OIDC sont enregistrés chiffrés en AES-256-GCM. Chaque champ secret de l'interface Paramètres dispose d'un switch de cadenas pour basculer entre clair et chiffré ; la clé maîtresse reste dans l'environnement, jamais sur disque. La rotation se fait en ligne via les clés héritées.
- [Variables d'environnement](https://docs.nomana-it.fr/fr/liberty/framework/configuration/environment-variables/): Chaque variable d'environnement LIBERTY_* documentée — URL de base de données, clé de signature JWT, clé maître de chiffrement, clé de licence, clé IA, répertoire d'applications, paramètres OIDC — avec le fichier qu'elle surcharge et la valeur par défaut appliquée quand elle n'est pas définie.
- [Rechargement à chaud](https://docs.nomana-it.fr/fr/liberty/framework/configuration/hot-reload/): Chaque édition de TOML par section faite dans l'UI Paramètres ou poussée via POST /admin/reload est appliquée au framework en cours d'exécution sans redémarrage. Cette page documente ce qui se recharge, ce qui reste en cours et ce qui demande un redémarrage du processus.
- [UI des Paramètres](https://docs.nomana-it.fr/fr/liberty/framework/configuration/settings-ui/): La page Paramètres in-app est l'éditeur piloté par schéma pour chaque fichier TOML par section : pools, connecteurs, dictionnaire, écrans, menus, tableaux de bord, graphiques et jobs. Un éditeur par concept, un éditeur Monaco brut comme échappatoire, et un bouton Recharger qui pousse chaque changement à chaud.
- [Connecteurs](https://docs.nomana-it.fr/fr/liberty/framework/connectors/): Un connecteur définit la manière dont le framework atteint une source de données. Créé et modifié depuis Paramètres → Connecteurs — trois types (SQL, HTTP, API), chacun avec son éditeur dédié. Le schéma est découvert à l'exécution à partir de la requête live ; rien n'est saisi à la main pour le type des colonnes.
- [Piste d'audit](https://docs.nomana-it.fr/fr/liberty/framework/cookbook/audit-trail/): Recette — peupler automatiquement les colonnes created_by, created_at, updated_by, updated_at à chaque écriture, sans faire confiance au client. Les valeurs par défaut LOGIN et SYSDATE de la couche formulaire du framework font le travail.
- [Import en masse](https://docs.nomana-it.fr/fr/liberty/framework/cookbook/bulk-import/): Recette — permettre aux opérateurs de téléverser un fichier CSV ou Excel et d'importer ses lignes dans une table. Validation par ligne, rapport des succès et échecs, base de données intacte en cas d'erreurs.
- [CRUD sur une table existante](https://docs.nomana-it.fr/fr/liberty/framework/cookbook/crud-existing-table/): Recette — prendre n'importe quelle table de base de données existante et produire une interface liste / édition / ajout / suppression fonctionnelle par-dessus en cinq clics dans les Paramètres. Le chemin le plus rapide de « j'ai une table » à « les utilisateurs s'en servent ».
- [Export Excel](https://docs.nomana-it.fr/fr/liberty/framework/cookbook/excel-export/): Recette — chaque écran livre un export Excel par défaut. Personnaliser la liste de colonnes, ajouter un export d'agrégation côté serveur, ou planifier un Excel quotidien envoyé par email.
- [Donner accès aux données à l'assistant IA](https://docs.nomana-it.fr/fr/liberty/framework/cookbook/expose-to-ai/): Recette — choisir les connecteurs que l'assistant IA peut lire, restreindre les écritures, rédiger une bonne description d'outil pour que le modèle choisisse la bonne requête. La différence entre un assistant utile et un assistant qui hallucine.
- [Téléversement de fichier](https://docs.nomana-it.fr/fr/liberty/framework/cookbook/file-upload/): Recette — permettre aux utilisateurs d'attacher des fichiers à une ligne (contrats, factures, photos) et de les retrouver depuis la même ligne. Deux modèles : stocker le fichier en base, ou stocker une référence et déporter vers un stockage objet.
- [Formulaire multi-étapes / workflow](https://docs.nomana-it.fr/fr/liberty/framework/cookbook/multi-step-form/): Recette — modéliser un workflow d'approbation avec transitions de statut, visibilité des champs par état, actions filtrées par rôle et relances planifiées. Les conditions de formulaire + les actions personnalisées du framework font le travail.
- [Connexion OIDC](https://docs.nomana-it.fr/fr/liberty/framework/cookbook/oidc-sso/): Recette — brancher le framework sur Authentik, Keycloak, Azure AD ou Okta en 10 minutes. Single sign-on, mapping groupes vers rôles, auto-provisionnement, accès de secours admin.
- [Accès au niveau de la ligne](https://docs.nomana-it.fr/fr/liberty/framework/cookbook/row-level-access/): Recette — donner à chaque utilisateur l'accès à ses propres lignes. Le commercial ne voit que ses clients ; le tenant ne voit que ses données. Le placeholder :session_user et une clause WHERE par requête font le travail — aucun code applicatif, aucun middleware en plus.
- [Rapport planifié par email](https://docs.nomana-it.fr/fr/liberty/framework/cookbook/scheduled-report-email/): Recette — chaque jour ouvré à 08:00, exécuter un agrégat SQL, le rendre en XLSX, l'envoyer par email à une liste de destinataires. Le job Nomaflow + l'étape http + l'endpoint d'export Excel du framework font le travail.
- [Tableaux de bord](https://docs.nomana-it.fr/fr/liberty/framework/dashboards/): Un tableau de bord agence des KPI, graphiques et tables au-dessus de requêtes de connecteur dans une grille responsive. Construit et modifié depuis Paramètres → Tableaux de bord avec des panneaux en glisser-déposer ; chaque panneau choisit une source de données, une visualisation et un drill-down optionnel.
- [Dictionnaire](https://docs.nomana-it.fr/fr/liberty/framework/dictionary/): Le dictionnaire regroupe les métadonnées qui transforment des colonnes brutes de base de données en interface lisible — libellés localisés, formats numériques, règles BOOLEAN / ENUM / LOOKUP, valeurs par défaut côté formulaire. Édité depuis Paramètres → Dictionnaire ; réutilisé partout où une colonne de connecteur est affichée.
- [Conditions de formulaire](https://docs.nomana-it.fr/fr/liberty/framework/form-conditions/): Afficher, masquer, rendre obligatoire ou désactiver un champ en fonction des valeurs en direct des autres champs du même dialogue. L'éditeur d'écrans propose trois emplacements de condition par champ — Visible quand, Obligatoire quand, Désactivé quand — avec un éditeur d'expression qui suggère les noms de champs et donne un aperçu de l'évaluation.
- [Première app pas à pas](https://docs.nomana-it.fr/fr/liberty/framework/getting-started/first-app/): Construire une app Liberty fonctionnelle de bout en bout en moins de cinq minutes : déclarer un pool de base de données, définir un connecteur SQL, présenter un écran avec une grille + dialogue d'édition et l'intégrer dans le menu latéral — le tout depuis l'UI des Paramètres, le tout rechargé à chaud.
- [Structure du projet](https://docs.nomana-it.fr/fr/liberty/framework/getting-started/project-layout/): Cartographie des fichiers des deux dépôts — liberty-next (binaire du framework) et liberty-apps (configuration spécifique à l'installation). Ce qui se trouve où, ce qui est versionné, ce qui est spécifique à l'installation, et comment LIBERTY_APPS_DIR aiguille le framework vers le dépôt apps.
- [Pourquoi Liberty Framework](https://docs.nomana-it.fr/fr/liberty/framework/overview/): Liberty Framework est une plateforme low-code pour construire des applications internes — outils d'administration, tableaux de bord BI, intégrations, portails clients — sans écrire de frontend. Définissez les sources de données et les écrans dans l'interface Paramètres ; le framework rend la grille, le dialogue d'édition, le tableau de bord, l'assistant.
- [Vues de grille enregistrées](https://docs.nomana-it.fr/fr/liberty/framework/saved-views/): Enregistrez les colonnes, le tri, les filtres et le regroupement d'une grille comme une vue nommée — vos vues vous suivent sur tous vos appareils, et un administrateur peut publier des vues partagées dont une par défaut. Inclut la Vue synthèse — lignes parents agrégées côté serveur avec chargement paresseux des lignes filles — et le filtre à la journée sur les colonnes horodatées.
- [Étape 1 — Mise en place du projet CRM](https://docs.nomana-it.fr/fr/liberty/framework/tutorial-crm/01-setup/): Démarrez le tutoriel Construire un CRM : installez le framework, créez une app crm vide, préparez les tables de la base que nous utiliserons sur les six étapes. État final : framework opérationnel, admin connecté, trois tables vides prêtes pour les clients, les affaires et les activités.
- [Étape 2 — L'écran Clients](https://docs.nomana-it.fr/fr/liberty/framework/tutorial-crm/02-customers/): Construisez le premier écran du CRM : un connecteur SQL qui lit + écrit la table customers, un écran qui le transforme en grille + dialogue d'édition, et une entrée de menu qui l'ouvre. Illustre le flux complet pool → connecteur → écran → menu.
- [Étape 3 — Affaires et relations](https://docs.nomana-it.fr/fr/liberty/framework/tutorial-crm/03-deals/): Ajoutez l'écran Affaires avec un lookup clé étrangère vers les Clients, polissez le dictionnaire pour que les valeurs de statut s'affichent en chips colorés, et ajoutez une sous-grille Activités à l'intérieur du dialogue de l'affaire. Illustre les lookups, le dictionnaire et les relations parent-enfant.
- [Étape 4 — Tableau de bord du pipeline commercial](https://docs.nomana-it.fr/fr/liberty/framework/tutorial-crm/04-dashboard/): Posez un tableau de bord au-dessus des données Affaires existantes : quatre KPI, un graphique en barres empilées par étape, une table « activités récentes », tous partageant un filtre de période et permettant le drill-down vers l'écran Affaires. Illustre les tableaux de bord, les graphiques et la barre de filtres partagée.
- [Étape 5 — Rôles et SSO](https://docs.nomana-it.fr/fr/liberty/framework/tutorial-crm/05-auth/): Séparez le CRM entre les rôles Sales (édition complète), Manager (lecture + tableau de bord) et Admin. - [Référence UBL](https://docs.nomana-it.fr/fr/nomaubl/references/ubl-reference/): Référence des champs UBL pour la réforme française de la facturation électronique — chaque champ BT avec son XPath, sa cardinalité et un exemple, regroupé par section (en-tête, vendeur, acheteur, TVA, totaux, ligne, etc.).
- [Notes de version](https://docs.nomana-it.fr/fr/nomaubl/release-notes/): Notes de version NomaUBL — chaque changement visible pour l'utilisateur livré dans la plateforme, version par version, dans l'ordre antéchronologique. Reflète la page Notes de version disponible dans l'application.
- [Récupération des entrées](https://docs.nomana-it.fr/fr/nomaubl/sync/fetch-input/): Automatisation en lot de Extract and Process — analyse d'un répertoire ou de la file d'impression BIP, sélection des éléments dans une liste à cocher, puis exécution du même pipeline Extract → Process sur chaque élément retenu.
- [Import](https://docs.nomana-it.fr/fr/nomaubl/sync/import/): Vérifier que les factures déposées sur la Plateforme Agréée ont effectivement été importées — interrogation asynchrone qui fait passer chaque facture en attente 9906 vers 10 (déposée) ou 9907 (import rejeté par la PA).
- [Récupération des statuts](https://docs.nomana-it.fr/fr/nomaubl/sync/retrieve-statuses/): Récupérer les événements de cycle de vie depuis la Plateforme Agréée — codes XP Z12-012 200, 201, 206, 207, 210, 213… — et les appliquer à la table de cycle de vie locale et à l'en-tête de facture. Récupération incrémentale par horodatage repère.
- [Remises / charges](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/allowances-charges/): Valeurs par défaut UBL — onglet Remises / charges. Texte et code de motif par défaut, par direction (BR-42 pour les remises, BR-43 pour les charges) ; `ChargeIndicator` choisit la paire au moment de l'émission.
- [Cadre de facturation](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/business-process-type/): UBL Defaults — onglet Business Process Type. Cadre de facturation français (BT-23) — nature de la facture (biens / services / mixte) et stade du cycle de vie (dépôt / déjà payée / définitive / sous-traitance / multi-vendeurs / e-reporting).
- [Pays & classification](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/country-classification/): Valeurs par défaut UBL — onglet Pays & classification. Format côté source du pays d'origine en ligne (BT-159) et repli sur le code de classification, le listID du schéma et sa version (BT-158).
- [Mappage des codes devise](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/currency-code-mapping/): UBL Defaults — onglet Currency. Devise par défaut (BT-5) et mapping source → code devise ISO 4217.
- [Type de document (routage BAR)](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/document-type-bar-routing/): UBL Defaults — onglet Document Type. Classification BAR (B2B / B2G / B2BINT / B2C / OUTOFSCOPE / ARCHIVEONLY / DOCUMENT) utilisée pour aiguiller le document au sein de la Plateforme Agréée.
- [Mentions légales françaises](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/french-legal-notes/): UBL Defaults — onglet Notes. Notes légales au niveau document (BT-22) portant les mentions obligatoires françaises — délai de paiement, indemnité de recouvrement, conditions générales — avec préfixe de type de note.
- [Type de facture](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/invoice-type/): UBL Defaults — onglet Invoice Type. Code de type de facture UBL par défaut (BT-3) et sélection par règles s'appuyant sur le XML source.
- [Vue d'ensemble](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/overview/): Fonctionnement des UBL Defaults de NomaUBL — un fichier de valeurs par défaut (ubl-defaults.xsl) et une couche de surcharge optionnelle par template, résolus groupe par groupe à la génération.
- [Mappage des codes paiement](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/payment-code-mapping/): UBL Defaults — onglet Payment. Code de moyen de paiement par défaut (BT-81) et mapping source → UBL fondé sur UNCL 4461.
- [Identifiants de schéma](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/scheme-ids/): UBL Defaults — onglet Scheme IDs. Identifiants de schéma ISO 6523 / UNTDID 1153 / EAS rattachés au SIREN, SIRET, GLN, à l'adresse électronique et au lieu de livraison.
- [Sociétés fournisseurs](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/suppliers-companies/): UBL Defaults — onglet Suppliers. Annuaire des sociétés vendeur (AccountingSupplierParty) utilisé comme valeurs par défaut quand le XML source les omet, indexé par code société.
- [Valeurs par défaut de l'en-tête UBL](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/ubl-header-defaults/): UBL Defaults — onglet Header. Version UBL, identifiant de personnalisation (BT-24), pays par défaut (BT-40 / BT-55) et format de date d'entrée par template.
- [Mappage des unités de mesure](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/unit-of-measure-mapping/): UBL Defaults — onglet Units. Code d'unité par défaut (BT-130) et mapping source → code UN/ECE Recommendation 20.
- [Catégories de TVA](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/ubl-defaults/vat-categories/): UBL Defaults — onglet VAT. Catégorie TVA par défaut, taux zéro, mapping source → catégorie UBL (BT-118 / BT-151) et mapping catégorie → code d'exonération VATEX (BT-121).
- [Validation](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/validate/): Valider un document UBL face au schéma XSD et aux règles Schematron — UBL direct ou XML amont transformé en UBL via le pipeline XSL d'un template.
- [Visualiseur XML](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/xml-viewer/): Ouvrir n'importe quel fichier XML — local ou serveur — dans un éditeur Monaco avec coloration syntaxique, mise en forme automatique, numéros de ligne et enregistrement serveur. Le complément léger du validateur et de l'Éditeur XSL.
- [Éditeur XSL](https://docs.nomana-it.fr/fr/nomaubl/ubl-tools/xsl-editor/): Mapper les champs d'un spool XML source vers les termes métier UBL 2.1 (codes BT) via un formulaire visuel — sans rédiger de XSLT à la main. Auto-mapping assisté par IA inclus.
