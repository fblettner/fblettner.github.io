# Versions Oracle

L'écran **Versions** catalogue les versions de base Oracle reconnues par Nomasx-1, associées au composant de licence dont chaque version dépend. Une ligne par `(Composant, Version)`. Le catalogue sert à classer les lignes des écrans *Base de données → Oracle* et *Licences → Oracle*.

Ajouter une nouvelle version ici est le préalable pour que Nomasx-1 lise une version d'Oracle fraîchement installée.

## Objectif de l'écran

- **Référencer les versions Oracle** prises en charge par Nomasx-1 et leur classification de licence.
- **Une ligne par (Composant, Version)** — un même composant peut couvrir plusieurs versions (Enterprise Edition en 19c et 21c, par exemple).

---

## Colonnes

| Colonne | Source | Ce qu'on y lit |
|---|---|---|
| **Version ID** | `VER_ID` — identifiant interne. | Clé numérique. |
| **Composant ID** | `VER_CPT_ID` — lié à *Pricing → Composants*. | Composant Nomasx-1 auquel la version est rattachée. |
| **Composant** | `CPT_COMPONENT` — libellé dénormalisé. | Nom de composant affiché. |
| **Version** | `VER_VERSION` — version majeure Oracle. | Chaîne de version (`19c`, `21c`, `23c`…). |

## Import depuis Excel \{#import\}

Les lignes se modifient par **Importer**, depuis un fichier Excel (`.xlsx`) ou `.csv` dont les colonnes reprennent celles de la grille : **Exporter** la grille, modifier le fichier puis le réimporter. L'import met à jour les lignes existantes, il n'en crée pas.

1. Déposer le fichier dans la fenêtre, puis cliquer sur **Vérifier** : chaque ligne est contrôlée au regard des règles de l'écran et de la base, et chaque ligne invalide est listée avec sa raison.
2. **Enregistrer N lignes valides** écrit les lignes valides ; les lignes invalides sont ignorées.

Le fichier porte les colonnes suivantes :

| Colonne | Contenu |
|---|---|
| **Version ID** | Clé — l'édition telle que la base la déclare. |
| **Composant ID** | Composant de licence correspondant. |
| **Version** | Libellé de l'édition. |

## Conseils & bonnes pratiques

- **Ajouter les nouvelles versions tôt.** Une montée de base lit une nouvelle valeur dans le dictionnaire Oracle — la collecte ne la classera pas tant que la version n'est pas déclarée ici.
- **Utiliser le libellé officiel Oracle** (`19c`, `21c`, `23ai`) pour rester aligné avec le price book.
- **Plusieurs versions pour un même composant est normal.** Les conserver toutes pour les parcs mixtes.
