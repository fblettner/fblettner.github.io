# Licences souscrites

La page **Licences souscrites** présente ce que couvre chaque contrat de licence, lu comme le lit la position de licences : les **bundles** du contrat (une seule licence pour tous leurs modules), ses **lignes d'un seul module, regroupées selon leur mode de comptage**, les **chiffres déclarés par le client** et, en marge, **le sens de chaque mode de comptage**. C'est la moitié « droits acquis » de l'équation de licence, pour chaque contrat de toute application connectée ; l'autre moitié, l'utilisation et ce qu'elle peut coûter, se trouve dans **Revues → Licences**.

La page est en lecture seule. Un contrat, ses lignes, ses bundles et ses chiffres déclarés se saisissent dans l'écran [CSI](./csi.md), que le bouton **Modifier les contrats** ouvre directement.

Accès : **Licences → Licences souscrites**.

## Un bloc par contrat \{#contract\}

Chaque contrat forme un bloc, dans l'ordre des identifiants. L'en-tête donne la description et le numéro du contrat, un badge **non actif** quand le contrat n'est pas en vigueur, sa période de validité (*du → au*) et les applications qu'il **couvre** — celles rattachées dans l'onglet *Applications* du contrat (*aucune application* sinon). Un contrat qui ne couvre aucune application ne compte pour aucune.

Le bloc comporte trois parties, chacune affichée seulement si elle contient quelque chose :

| Partie | Contenu |
|---|---|
| **Bundles** | Une carte par bundle du contrat : nom et code, quantité et métrique, modules regroupés (*aucun module pour l'instant* s'il est vide). Une licence compte pour tous les modules du bundle. |
| **Lignes d'un seul module** | Les lignes du contrat portant sur un seul module, un tableau par mode de comptage : *Module*, *Métrique*, *Souscrit*. |
| **Déclaré par le client** | Les chiffres déclarés pour le contrat, datés : *Le*, *Chiffre d'affaires (millions)*, *Employés*, *Commentaire*. *Rien de déclaré.* si la liste est vide. |

Les noms de modules sont abrégés : le préfixe *JD Edwards EnterpriseOne* est omis.

## Comment une ligne est comptée \{#how-counted\}

Une ligne est classée selon sa métrique. Le panneau latéral de la page reprend ces explications, avec la période de connexion de l'application et le facteur de cœur en vigueur.

| Groupe | Métriques | Élément de comparaison |
|---|---|---|
| **Comptée en utilisateurs** | Application User, Named User Plus sur un module applicatif | Chaque utilisateur activé compte pour une licence, sur les modules qu'il a utilisés — ou, sans suivi d'utilisation, sur ceux que sa sécurité autorise s'il s'est connecté pendant la période de l'application (90 jours par défaut). Un bundle est essayé avant le module seul, le plus petit qui convient en premier. |
| **Comptée en utilisateurs nommés** | Named User Plus sur une base de données, une option ou un pack | Pas utilisateur par utilisateur — JD Edwards se connecte à la base avec un seul compte — mais un décompte : les utilisateurs JD Edwards activés des applications du contrat, les comptes ouverts de la base qui ne sont pas ceux d'Oracle et les utilisateurs déclarés pour les autres applications ; jamais sous le minimum par processeur de la liste de prix. Une option ou un pack Enterprise suit sa base. |
| **Comptée sur le chiffre d'affaires** | Enterprise $M | La ligne couvre ses modules pour tout le monde ; sa quantité est un chiffre d'affaires en millions, comparé au chiffre d'affaires déclaré pour le contrat. |
| **Comptée sur les employés** | Employee | La ligne couvre ses modules pour tout le monde ; elle est comparée aux employés déclarés, à défaut à ceux collectés dans l'application. |
| **Comptée sur les processeurs** | Processor | Comparée aux cœurs des serveurs de base de données multipliés par le facteur de cœur de leur puce (0,5 pour Intel et AMD) ; une machine virtuelle compte tous les hôtes physiques de son cluster. Les tailles sont celles saisies dans l'écran [Taille des serveurs](../../nomajde/monitoring/server-sizes.md#processor-licences) de nomajde, à défaut le nombre de CPU collecté. |
| **Non comparée** | Concurrent User, Expense Report, Stream… | La ligne couvre ses modules ; aucune comparaison n'est faite. |

:::info[Spécifique à JDE]
L'utilisation retenue pour *Comptée en utilisateurs* provient d'Object Usage Tracking, et les employés collectés proviennent de JD Edwards EnterpriseOne. Pour une autre source, les lignes se lisent de la même façon ; l'utilisation est celle que collecte son connecteur.
:::

## Conseils & bonnes pratiques

- **Vérifier les groupes avant de lire la position.** Une ligne mal classée signale presque toujours une métrique erronée sur la ligne de contrat — à corriger dans l'écran [CSI](./csi.md).
- **Déclarer le chiffre d'affaires et les employés** d'un contrat qui comporte une ligne *Enterprise $M* ou *Employee* : sans chiffre déclaré, aucune comparaison n'est possible.
- **Saisir les bundles en premier.** Quand le contrat vend des modules sous forme de suite, saisir le bundle avec ses modules : un utilisateur de deux d'entre eux occupe alors une seule licence, et non deux.
- **Interroger l'assistant.** Il reçoit le nombre de contrats et de bundles affichés sur la page.
