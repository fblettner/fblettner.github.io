# A menu

In **Security Management**, the starting point **a menu** answers *who sees this task?* for one place of a JD Edwards EnterpriseOne menu. Pick a task view: its menu is drawn as a tree on the left; click a task or a folder, and the roles are listed beside it, **Everybody** (`*PUBLIC`) first, each with whether the task is shown to it.

Open it from **Security Management**, then **Start from → a menu**. The other starting points are described in the [Security Management overview](./overview.md).

## The menu \{#tree\}

- **Task view** picks the menu to draw; the page opens on the largest task view.
- The tree shows each task with its menu code and, for a task that runs an object, the object and its version. A folder opens and closes with its arrow; **Collapse all** closes them all.
- **Find a task, a menu, an object…** searches the tree by task name, menu code or object.
- A click on a task or a folder picks that place in the menu: a task under two folders is two places.

JD Edwards filters menus by role only: the list beside the tree holds the roles, not the users. A user sees the menus of the roles held.

---

## Who sees a task \{#who-sees\}

The panel **Who sees** *task* lists the roles with one box, **Shown**, and a search (*Find a role…*):

- A role sees a task unless a line hides it: without a line, the box is ticked and **Why** says *no line of its own*.
- A role whose own line hides the task has its box unticked, and **Why** says *its own line*.
- A hidden folder hides everything below it.

### Hide or show \{#change\}

- **Untick a box** to hide the task from a role: the menu-filtering line is added (or the role's line is set to hidden).
- **Tick it again** to show the task: the line that hid it is removed — showing never adds a line.
- **The box in the heading** sets every role listed (after a search: those found), never *Everybody*.
- Changes wait for **Save**; **Discard** drops them. Changing *Everybody* asks first.

The lines are written through the [Menu Filtering](../security-maintenance/menu-filtering.md) screen's own queries, so they are checked, stamped and captured in the change package as a change made in that screen.

A role's code is a link: it opens that role in the starting point **a user or role**, on its **Menus** tab, where its whole menu can be ticked at once.

## Access \{#access\}

The page is **Security Management** in the Nomajde menu; the predefined roles **Security administrator** and **Administrator** hold it (see [Predefined roles](../overview.md#roles)).

## Tips & best practices \{#tips\}

- **Hide a folder rather than each task**: one line is enough, and the tasks added to the folder later are hidden too.
- **Start from a menu** to answer a question about one task; start from **a user or role** to rework one role's whole menu.
- **Read the lines as a list** in [Menu Filtering](../security-maintenance/menu-filtering.md) to export them, change them in bulk or load them from a file.
- **Remember that a menu is not a security**: hiding a task does not stop a role from running its object — that is the job of the [application security](./object.md).
